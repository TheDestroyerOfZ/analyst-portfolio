PERSONAL PROJECT / DOCUMENT ANALYSIS & STUDY TOOLS

Make the material searchable.
Make the learning active.

Study Helper and Ask My Documents are two related personal applications for working with course material: one creates revision outputs, while the broader study hub combines document retrieval, notes, quizzes, and planning.

Unstructured dataInformation retrievalSource traceabilityStudy workflows

The problem the tools address

Course information is spread across documents and notes. Finding a relevant passage and turning it into material for revision are different tasks. These tools bring those activities into local applications while keeping the source material available for checking.

Two related tools, distinct capabilities
ToolInput and processingUseful output
Study HelperPDF and text-based notes, grouped by subject. Extracted text is used to generate study material; subject-based questions can identify the source file.Study sheets, summaries, flashcards, and Anki export.
Ask My Documents / Study HubA broader document collection, including Word and PowerPoint, with OCR support and a retrieval index.Source-linked answers, quizzes, notes, revision features, and a planning dashboard.

From documents to useful information

Read source documents?Extract and organise text?Find relevant passages?Answer or build revision material

The broader hub breaks extracted text into passages and uses local embeddings together with keyword retrieval to find relevant material. Generation uses the retrieved context; references let the user return to the source. This is a design for grounded answers, not a guarantee that generated text is correct.

Why it belongs in an analytics portfolio

The analytical work here concerns unstructured information: extracting it, organising it, retrieving relevant evidence, and presenting useful outputs. It complements the portfolio?s numerical reporting and statistical projects. It is not a claim of measured improvements in grades, retrieval accuracy, or time saved.

Capabilities and evidence

  • Implemented in the projects: document extraction, subject organisation, revision outputs, and source-based question workflows.
  • Verified locally: the broader hub?s active document configuration, dashboard response, and unchanged PDF delivery across four course folders.
  • Still to evaluate: answer correctness, citation quality, OCR accuracy, and the usefulness of generated study material against a fixed test set.

This portfolio describes the implementation and publishes no course material, notes, marks, or cached document passages. It does not host the private study applications.

A concrete change: keeping document access reliable

The following migration provides a specific example of how a user need became a configuration change and a set of checks. It supports the wider project story.

The change in one sentence

Keep the familiar study launcher, but make the copied application use the copied documents while preserving the original workspace as a fallback.

VERIFIED: document configuration, dashboard response, and document delivery across four course folders.

1. Understand the need

The project owner requested a copy of an existing collection of applications, then asked to use the new folder as the active workspace. A specific condition was that the study launcher should still bring up the documents. Privacy later became an explicit requirement for any material published from the PC.

Scope: the copied study hub, its launcher, its document-location configuration, and cached file references. The original workspace remained a fallback. The local AI installation stayed a shared dependency.

Outside this change: cloud hosting of the study service, redesigning retrieval, validating every AI answer, or publishing course materials.

2. Identify the dependency

The application reads a document-location setting from study_folder.txt. After copying, that setting still referred to the original folder. Launching the copied application could therefore continue reading and writing in the old document collection.

Copied launcher→Copied application→Old absolute setting→Original documents

The setting was changed to a relative path resolved from the application’s program directory. Cached document paths were also migrated, retaining the existing search vectors.

Copied launcher→Copied application→Resolved relative setting→Copied documents

These diagrams describe the document-location dependency, not every background task in the application.

4. Explain the technical flow

The launcher starts a Python service on the local computer. The service resolves the document folder, loads its search cache, and serves the browser dashboard. Document requests are handled by the local service. Question-answering separately uses a local Ollama API for retrieval embeddings and generated answers.

This distinction matters in testing: successfully opening a PDF verifies document delivery, but does not demonstrate answer accuracy or reliable citations.

6. Make the trade-offs visible

  • Relative configuration: reduces dependence on one absolute location, but the expected relationship between program and document folders must remain intact.
  • Shared AI service: avoids duplicating the model installation, but means the copied app is not a fully isolated environment.
  • Preserved fallback: keeps the original available, but edits in the two collections do not synchronise automatically.
  • Focused verification: provides evidence for the document-access requirement while leaving other workflows explicitly unverified.

What this case demonstrates

A concrete user request can be translated into scope, a dependency map, testable criteria, and evidence. The next checks would cover a disposable note, missing-folder handling, unavailable AI services, and a complete desktop launch. Each would add confidence in a different part of the service.
